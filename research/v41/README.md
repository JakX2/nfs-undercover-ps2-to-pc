# V41: source-verified RedBuilding 1B / 1C / 1Z native Carbon PC geometry library

**OFFLINE research only. Not installable and not tested in the running Carbon PC game.** This package does not modify original `L5RA.BUN`, `STREAML5RA.BUN`, your Carbon installation, or any game executable.

## What was verified

We started with (1) the exact original Undercover Wii RedBuilding `0x80134000` group from the user's game archive, (2) the V33 native Carbon-PC-formatted single-object RedBuilding 1B donor, and (3) an original Wii `0x80034100` scene containing a real 1B placement record.

The original Wii group has exactly three GX components:

| Component | Wii position entries | Wii nondegenerate faces | Carbon PC seam-aware vertices | Carbon PC faces | Source object hash |
|---|---:|---:|---:|---:|---|
| `XBU_REDBUILDING_1B_00` | 200 | 260 | 400 | 260 | `0x80B4A527` |
| `XBU_REDBUILDING_1C_00` | 122 | 146 | 239 | 146 | `0x80B53188` |
| `XBU_REDBUILDING_1Z_00` | 54 | 58 | 92 | 58 | `0x80C1CE3F` |
| **Combined** | **376** | **464** | **731** | **464** | |

All three original Wii components reference the **same** source texture `0x2CAB30BD` (`ARC_REDBUILDING_01`). In each converted PC component the V19 decoder reads back every triangle with source winding, XYZ float32 coordinates, RGBA values, and texture coordinates (original GX signed UV integers / 2048). The 1C and 1Z output meshes use a 36-byte single-material Carbon vertex layout and source-independent V20 averaged normals: **these normals are approximations, not original Wii normals**. All object-local 4x4 matrices match the original Wii 64-byte values, and all converted AABBs obey the original Carbon PC 0.01-unit expansion rule.

The preexisting V33 1B component is preserved **byte for byte**. The new 1C and 1Z components have source-derived identity hashes; their PC mesh records were generated by using the prevalidated V33 1B as a *layout donor* and preserving the original Wii geometry and per-corner attributes. Each component has its own distinct hash entry in the native `0x134003` sorted directory. The catalogue's `0x134002` count is now three, while its PC section `0x3058`, name `eLabScenery_XBu_RedBuilding_1.bin`, and platform-specific metadata are retained.

**Native root output:** `samples/RedBuilding_1B_1C_1Z_Native_PC_V41.chunk` (31,132 bytes). It is a *standalone model library file-format proof*, NOT a world-stream patch.

## Placement reference check

The original Undercover Wii `XBu_RedBuilding_1b_00` 72-byte `0x34102` information row holds four LOD slots:

- Wii source: `[0, 0x80B4A527, 0x80B53188, 0x80C1CE3F]`.
- Offline PC-style *candidate*: `[0x80B4A527, 0x80B4A527, 0x80B53188, 0x80C1CE3F]`.

The only candidate edit is filling the previously zeroed first field at byte offsets `0x18..0x1B` with the native 1B hash (fallback in absence of 1A). All four references resolve to the new three-object catalogue. The original 96-byte placed-instance record remains byte-for-byte unchanged. **This is not proof the PC streamer will accept the scene or that LOD switching works in-game.** It still requires sector registration, PC-specific metadata checks, and a runtime test.

## Explicit limitations

- Source RedBuilding 1C/1Z materials use the verified original Wii texture hash, **but the actual shader implementation and appearance inside Carbon PC are not yet verified**. The inherited Carbon carrier still includes an auxiliary dependency `0x25A033BB`, which must be investigated rather than silently removed.
- The separate V25 native PC texture-pack prototype is **not part of a registered, installable world mod**.
- Neither `0x34103` instance insertion nor the PC `0x34110` streaming index was changed.
- Collision, navigation, world placement, LOD streaming policies, source lighting and gameplay remain unfinished.
- This source-verified model is the **1B/1C/1Z family only**. The V38 26 RedBuilding-family placements include four `2B`-named models, which are not included here.

## Reproduce

Python 3.10+ is sufficient to build and test the raw binary artifacts:

```bash
cd bridge_v41
python -m unittest test_v41 -v
python native_redbuilding_lods_v41.py \
  --pc-v33 UC_RedBuilding_Standalone_CarbonPC_V33.chunk \
  --uc-wii-source undercover_redbuilding_wii.chunk \
  --uc-wii-scene UC_Wii_RedBuilding_Original_Scene.chunk \
  --output-dir rebuilt_offline
```

Source inputs have exact SHA-256 guard checks; the code rejects any unrecognized changes to the Wii source or PC donor. It only writes new research outputs to a separate directory. Optional preview models were exported by `export_v41_preview.py` (requires `numpy`, `trimesh`). Those GLBs use the corrected Y-up glTF coordinate convention and vertex colors but are *not* proof of final shader/texture appearance.
