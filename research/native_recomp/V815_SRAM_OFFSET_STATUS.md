# V815: offset-addressed SRAM protocol

V812 identified original wireless-ID get/set wrappers sharing UnlockSram and EXI dependencies. The existing MX endpoint only accepted the base SRAM address; public libogc's `__sram_write` establishes that an SRAM update can begin at a byte offset encoded in the EXI command (https://github.com/devkitPro/libogc/blob/master/libogc/system.c). Implement independently within the existing bounded 64-byte device window, preserve RTC behavior, reject out-of-window or noncanonical commands, and retain token-based scheduler completion. The original-free regression covers every start offset, chunked writes, offset immediate readback, full DMA readback, selection epochs, dirty state, untouched bytes and eight negative controls. No original code, console data or persistence is added. Actual original wireless-ID behavior remains to be tested. CI pending.
