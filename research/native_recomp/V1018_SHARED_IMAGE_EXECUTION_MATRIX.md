# V1018: one native image, three isolated second IRQ launches

A full-image run currently spends most of its time authenticating, translating and linking the same original functions. This change installs the V1014 superset once, links once, then invokes the existing bounded launcher three times with clean per-lane HOME/config/SRAM/SI/log directories. Fixed lanes are absent-controller V1015 completion, mixed-controller V1009 callback prefix, and mixed-controller V1014 time continuation. Earlier device/IRQ guards are retained in all three. The mixed time mode is explicitly allowed to use the fixed port-one response. No guest context, MMIO state, logs or private binary are reused between processes; only the authenticated native executable is reused. Every lane is attempted even on audit failure; aggregate success requires all audits to return zero, which may include a classified non-callback boundary, not full startup. Existing single-run modes are unchanged. The private workflow leaves no artifacts. Source tests validate the actual launch plans and required build flags without owner inputs. Pending CI.
