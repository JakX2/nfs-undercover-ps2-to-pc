# V24: continuous original Wii startup reaches DBInit and OSInit boundary

This **source-only** toolkit extends the prior V23 NWiiRecomp native-execution proof by using the original Undercover Wii `__start` after `__init_data`, along the ordinary low-memory boot path. It enters the **original 40-byte `DBInit`** routine at `0x804E5020` and makes the original `bl OSInit` at `0x8000415C`, stopping at a **clearly synthetic** `sc; blr` fixture placed at `0x80520670`. The real `OSInit` (1,412 bytes) has **not** executed. The path does not display a frame or enter game `main`.

## Source-grounded implementation

- The owner DOL is checked against SHA-256 `16a09adcf1987c1f3617d10f3a1cb830f32886afb583f9f8f88e0963ae5fe1f4` before extraction. Original guest instructions are copied **only** from the private owner-supplied DOL at runtime.
- The original `__start` path from entry `0x8000403C`, through `__init_registers`, `__init_hardware`, `__init_data`, the low-memory startup bookkeeping and `DBInit`, is preserved for the **tested ordinary boot mode** (low-memory fields `0x800000F4` and `0x80000034` are zero).
- The conditional alternative firmware/boot operations at `0x800040C8` and `0x800040DC` are **replaced by explicit test-only syscall stops**. The test never takes those paths. The continuation just after the OSInit call is also a test-only `blr`, included to bound analysis. This is not a faithful entire `__start` function for arbitrary Wii boot configurations.
- `DBInit` performs the genuine guest-visible writes to `0x80000048`, `0x8070D8A0`, and `0x8070D8A4`. Its original function writes pointer `0x004E5090`, memory base `0x80000040`, and initialization flag `1`. The original startup also clears `0x80000044`.
- In the private original image, NWiiRecomp Analyzer discovers **26** functions. The independent synthetic fixture discovers **21**; synthetic DBInit uses separately hand-authored PPC instructions and writes a marker to `0x80037000`.
- `DBPrintf`, `OSSetErrorHandler`, and `OSInit` remain synthetic test service boundaries; Wii OS global state, cache coherency and video/audio are not implemented here. L2CR handshake remains deterministic, not timing-accurate.
- NWiiRecomp's non-split `run_game(CPUContext&)` dispatcher is actually generated by upstream C++; no handwritten call graph and no PowerPC interpreter fallback in tested paths.

## Reproduce

Use a private copy of the NWiiRecomp source tree, Python 3, and a C++20 compiler. The script patches only that provided local checkout and creates generated game C++ **only inside `mktemp -d`**, deleted on exit.

```bash
bash run_v24_tests.sh /private/NWiiRecomp-master
bash run_v24_tests.sh /private/NWiiRecomp-master /private/NfsMWRelease.dol.bin
V24_SANITIZE=1 bash run_v24_tests.sh /private/NWiiRecomp-master /private/NfsMWRelease.dol.bin
```

The runner installs the earlier original-free V15, V18, V19, and V20 runtime patches idempotently. Older upstream non-split generation emits an unsigned `ctx.gpr[x] < 0` comparison in untaken boot paths: the test build specifically disables `-Wtype-limits` while otherwise retaining `-Werror`. This is a **warning workaround**, not proof that all generated code is warning-clean. Some generated dispatcher versions print harmless PC-history debugging to stderr when the synthetic stop returns.

## Verified results (local execution)

| Test | Result |
| --- | --- |
| Original DOL, 16 native contiguous startup runs | **15,417,308 assertions passed** |
| Independent synthetic DOL, 16 native runs | **1,912 assertions passed** |
| Original `DBInit` call count | Exactly one per trial |
| Original boot state | Low-memory clear and all three DBInit stores correct |
| Guest stack and LR | Return to `0x80004160`, caller frame preserved |
| Original `__init_data` | 963,456 BSS bytes cleared per run, excluding 8 bytes later written by DBInit |
| Invalid input, overwritten file, wrong signature, boundary validation | **40 rejection checks passed** |
| GCC optimized and GCC AddressSanitizer/UndefinedBehaviorSanitizer | Both original and synthetic native test binaries passed |

**Important:** `OSInit` is only a synthetic stop, reached by the original PowerPC `bl`. These results do **not** establish Wii OS initialization, game `main`, graphics, audio, or a playable PC port. The next engineering goal is to audit `OSInit`'s original first dependencies and execute a small bounded prefix with accurate guest OS state, without silently mocking unimplemented services.

## Source files

- `make_start_to_dbinit_v24.py`: SHA-pinned, private original DOL slicer and independent synthetic fixture. Requires V23/V21/V17 source-only modules included in this package.
- `generate_start_to_dbinit_v24.cpp`: checked DOL parser and actual NWiiRecomp C++ emitter, with explicit guest stop and function-contract validation.
- `test_start_to_dbinit_v24.cpp`: original-free CPU/MMU register and memory assertions on privately generated functions.
- `test_start_guards_v24.py`: 40 owner-mode negative tests and source-publishing/overwrite guards.
- `run_v24_tests.sh`: reproducible release/sanitizer runner with temporary output cleanup.
- `audit_osinit_v24.py`: SHA-pinned original Wii `OSInit` direct-call census. The verified 1,412-byte function has 59 direct `bl` edges to 54 distinct targets. It prints only addresses and never emits game bytes.

Do not distribute original Wii DOL/ELF files, temporary extracted PPC code, generated game-function C++, or game assets. Preserve the draft research PR.
